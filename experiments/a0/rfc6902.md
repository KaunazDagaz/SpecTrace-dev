Here is the complete list of normative requirements extracted from the RFC 6902 specification, along with the exact quote and a corresponding test case for each.

---

### 1. Operation Object 'op' Member

* **Exact Quote:** "Operation objects MUST have exactly one "op" member, whose value indicates the operation to perform."


* **Test Case Title:** Missing 'op' Member
* **Input:**
* Target Document: `{"foo": "bar"}`
* Patch Document: `[{"path": "/foo", "value": "baz"}]`


* **Expected Result:** Error/Failure because the operation object lacks the required `"op"` member.

---

### 2. Valid Operation Values

* **Exact Quote:** "Its value MUST be one of "add", "remove", "replace", "move", "copy", or "test"; other values are errors."


* **Test Case Title:** Invalid Operation Name
* **Input:**
* Target Document: `{"foo": "bar"}`
* Patch Document: `[{"op": "invalid_op", "path": "/foo", "value": "baz"}]`


* **Expected Result:** Error/Failure because the `"op"` value is not one of the allowed operations.

---

### 3. Operation Object 'path' Member

* **Exact Quote:** "Additionally, operation objects MUST have exactly one "path" member."


* **Test Case Title:** Missing 'path' Member
* **Input:**
* Target Document: `{"foo": "bar"}`
* Patch Document: `[{"op": "remove", "value": "bar"}]`


* **Expected Result:** Error/Failure because the operation object lacks the required `"path"` member.

---

### 4. Ignoring Undefined Members

* **Exact Quote:** "Members that are not explicitly defined for the operation in question MUST be ignored (i.e., the operation will complete as if the undefined member did not appear in the object)."


* **Test Case Title:** Unrecognized Operation Member Ignored
* **Input:**
* Target Document: `{"foo": "bar"}`
* Patch Document: `[{"op": "add", "path": "/baz", "value": "qux", "xyz": 123}]`


* **Expected Result:** Success; the member `/baz` is added with value `"qux"`, and the extra undefined `"xyz"` member is ignored.

### 18. Error Handling and Termination

* **Exact Quote:** "If a normative requirement is violated by a JSON Patch document, or if an operation is not successful, evaluation of the JSON Patch document SHOULD terminate and application of the entire patch document SHALL NOT be deemed successful."


* **Test Case Title:** Patch Evaluation Termination on Error
* **Input:**
* Target Document: `{"a": {"foo": 1}}`
* Patch Document: `[{"op": "replace", "path": "/a/b/c", "value": 42}, {"op": "add", "path": "/a/d", "value": 100}]`


* **Expected Result:** Error/Failure; evaluation terminates immediately upon the first failing operation (`/a/b/c` does not exist), and subsequent operations are skipped, leaving the target document completely unchanged.
