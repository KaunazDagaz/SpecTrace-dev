### 1. Registry Registration of Elements

* **Requirement Quote:** "The JSContact elements MUST be registered in the IANA "JSContact" registry group [IANA.jscontact]."


* **Test Case:**
* **Title:** Validating Registered JSContact Elements
* **Input:** A profile containing elements registered in the IANA "JSContact" registry group vs. unregistered custom elements.
* **Expected Result:** Elements registered in the IANA registry pass validation, whereas unregistered custom elements trigger a validation error.



---

### 2. Prohibition of Loosening Restrictions

* **Requirement Quote:** "A profile MAY define additional restrictions for these elements as outlined in Section 3.3, but a profile MUST NOT loosen restrictions."


* **Test Case:**
* **Title:** Preventing Loosened Restrictions
* **Input:** A profile that attempts to broaden or loosen the original property type definition or constraints of a standard JSContact element.
* **Expected Result:** The profile definition is rejected as invalid because restrictions cannot be loosened.



---

### 3. Compliance and Validity of Object Properties

* **Requirement Quote:** "All properties and values of a JSContact object that complies with a profile MUST also be valid (Section 1.7 of [RFC9553])."


* **Test Case:**
* **Title:** Validating Object Properties Against RFC 9553
* **Input:** A JSContact object that adheres to profile restrictions but contains a property value invalid under base JSContact rules ([RFC9553]).
* **Expected Result:** The object fails validation due to core JSContact invalidity.



---

### 4. Profile Name Character Set

* **Requirement Quote:** "The name MUST only contain ASCII lowercase alphabetic and numeric characters, optionally separated by hyphens."


* **Test Case:**
* **Title:** Profile Name Character Validation
* **Input:** Two profile names: `my-profile-1` and `My_Profile!`.
* **Expected Result:** `my-profile-1` is accepted; `My_Profile!` is rejected because it contains uppercase letters, underscores, and special characters.



---

### 5. Profile Name Start Character and Length

* **Requirement Quote:** "It MUST start with an alphabetic character, and it MUST be of at least 1 character and at most 255 characters in size."


* **Test Case:**
* **Title:** Profile Name Start and Length Validation
* **Input:** Three profile names: `123profile`, `a`, and an empty string `""`.
* **Expected Result:** `a` is accepted; `123profile` is rejected (does not start with an alphabetic character); `""` is rejected (violates the minimum length of 1).



---

### 6. Profile Versioning Rules

* **Requirement Quote:** "The version MUST be a positive integer, and it MUST increase whenever the profile properties (see Section 3.3) change."


* **Test Case:**
* **Title:** Profile Version Increment Check
* **Input:** A profile update where properties change, updating the version number from `1` to `2` versus keeping it at `1`.
* **Expected Result:** Incrementing to `2` is accepted; keeping it at `1` after property changes is rejected.

### 7. Non-Empty Property Entry List

* **Requirement Quote:** "The list MUST NOT be empty."


* **Test Case:**
* **Title:** Verifying Non-Empty Property Entries
* **Input:** A profile definition containing zero property entries versus a profile definition containing at least one valid property entry.
* **Expected Result:** The profile with zero entries is rejected; the profile with property entries is accepted.

### 8. Property Name Registry Reference

* **Requirement Quote:** "This MUST be a property name registered in the "JSContact Properties" registry."


* **Test Case:**
* **Title:** Validating Property Name Against Registry
* **Input:** A property entry using a registered property name (`addresses`) versus an unregistered property name (`fooBar`).
* **Expected Result:** `addresses` is accepted; `fooBar` is rejected.

### 9. Prohibition of Conflicting Restrictions

* **Requirement Quote:** "...such multiple entries MUST NOT result in conflicting restrictions for the same property."


* **Test Case:**
* **Title:** Detecting Conflicting Property Restrictions
* **Input:** Multiple property entries for the same property that specify contradictory type or enum restrictions.
* **Expected Result:** The profile definition is flagged and rejected due to conflicting restrictions.

### 10. Restricted Value Type Matching

* **Requirement Quote:** "If set, the restricted value type MUST exactly match the original definition at the time when the profile is defined, or the original value type MUST contain some type signature in the form "A|B" and the restricted value type MUST resemble the original except that some of the original "A|B" forms now only allow a subset of the original choices."


* **Test Case:**
* **Title:** Validating Restricted Value Types
* **Input:** Restricting a `PartialDate|Timestamp` union type to `PartialDate` versus restricting it to an entirely unrelated type `String`.
* **Expected Result:** Restricting to `PartialDate` is accepted; restricting to `String` is rejected.

### 11. Prohibition of Redefining defaultType

* **Requirement Quote:** "Restricted property types MUST NOT redefine the "defaultType" attribute (Section 1.3.3 of [RFC9553]); the rules about when to set the "@type" property (Section 1.3.4 of [RFC9553]) of the original type definition still apply."


* **Test Case:**
* **Title:** Preventing defaultType Redefinition
* **Input:** A profile restriction that attempts to modify the `defaultType` attribute of a property type definition.
* **Expected Result:** The restriction is rejected.

### 12. Enumerated Values Registry Listing

* **Requirement Quote:** "The values MUST be listed in the "JSContact Enum Values" registry for this property and context."


* **Test Case:**
* **Title:** Validating Restricted Enum Values
* **Input:** Restricting an enum property to values present in the "JSContact Enum Values" registry versus values not listed there.
* **Expected Result:** Registry-listed values are accepted; unlisted values are rejected.

### 13. Mandatory Default Enum Exclusion Enforcement

* **Requirement Quote:** "...in which case all instances of the object MUST have this property set to one of the allowed values."


* **Test Case:**
* **Title:** Verifying Object Instances with Excluded Default Enums
* **Input:** An object instance lacking the property when the default value has been excluded by the profile vs. an instance explicitly setting the property to an allowed value.
* **Expected Result:** The instance lacking the property is rejected; the instance with an allowed value passes.

### 14. PatchObject Value Type Condition for "yes"

* **Requirement Quote:** "This MUST NOT be set to "yes" if the property value type is not a PatchObject."


* **Test Case:**

* **Input:** Setting `Restricted PatchObject: yes` on a property whose value type is a `PatchObject` versus a property whose value type is a standard `String`.
